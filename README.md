# AI 사용 구조 비교 (mes-ai-method-compare)

같은 코드·문서에서 **AI 사용 구조**(에이전트·스킬·`CLAUDE.md`·규칙)만 바꿔 같은 작업을 시키고,
**토큰 · 작업 시간 · 품질(사람 판정)** 을 비교해 좋은 구조를 고르기 위한 Claude 스킬과 도구입니다.

- 스킬: `skills/mes-ai-method-compare/SKILL.md` — Claude가 따라 하는 작업 지침
- 도구: `tools/mes-compare/mes_compare.py` — 기록·훅·대시보드를 처리하는 파일 하나 (Python 3.8+ 표준 라이브러리만 사용, 설치할 패키지 없음)
- 예시: `examples/` — 시험 데이터로 만든 대시보드, 설정 예시

git·SVN 모두 지원합니다. 서버(git 원격·SVN)에 아무것도 올리지 않고 내 컴퓨터에서만 동작합니다.

## 무엇을 비교하나

| 고정 (모든 구조에서 같게) | 바꾸는 것 (구조) | 측정 |
|---|---|---|
| 코드, `docs/` 설계 문서 등 참조 파일 | `CLAUDE.md`, `CLAUDE.local.md` | 사람 판정 합격률 · 첫 시도 합격률 |
| 작업 목록과 작업 설명 | `.claude/agents` (에이전트) | 작업당 토큰 |
| 검증 기준과 판정 기준 | `.claude/skills` (스킬) | 작업 시간 (AI 시작~종료) |
| 모델, 새 세션으로 시작 | `.claude/rules`, `.claude/commands`, `.mcp.json`, 플러그인 | 재작업 횟수, 실제 호출한 스킬·참조 파일 |

### 용어

| 용어 | 뜻 |
|---|---|
| **섹션** | 구조 하나 = 작업 폴더 하나. 같은 코드를 폴더 여러 개로 받아 두고 폴더마다 AI 설정만 다르게 둡니다. 폴더 이름이 구조 이름이 됩니다. |
| **세션** | 실행 하나. 섹션 안에서 작업 하나를 할 때마다 새 세션을 엽니다. |
| **작업** | 비교 단위. 같은 작업 ID를 두 구조가 실행한 것끼리만 비교합니다. |
| **프로젝트** | 저장소 이름(자동). 여러 프로젝트를 한 대시보드에서 볼 수 있습니다. |

```
상위 폴더/
 ├─ 기본/        ← 섹션 = 구조 "기본"  (공용 규칙·스킬 없음)
 ├─ 현재/        ← 섹션 = 구조 "현재"  (지금 쓰는 구성)
 ├─ 리뷰/        ← 섹션 = 구조 "리뷰"  (현재 + 검증 에이전트)
 └─ mes-compare-data/   ← 기록 폴더 (SVN·기타일 때 자동 생성)

비교:  T01@기본 ↔ T01@현재 ↔ T01@리뷰   (같은 작업끼리)
결론:  T01, T02, T03 … 를 모아 "현재는 기본 대비 토큰 −25%, 합격률 +10%p"
```

## 설치

### 1. 도구 두기
`tools/mes-compare/mes_compare.py`를 내 컴퓨터 아무 폴더에 둡니다. 예: `D:\tools\mes-compare\mes_compare.py`
(프로젝트 저장소나 SVN에 올릴 필요 없습니다.)

### 2. 스킬 등록
- **Claude Code**: `skills/mes-ai-method-compare/` 폴더를 `~/.claude/skills/` 아래에 복사합니다.
  (Windows: `%USERPROFILE%\.claude\skills\mes-ai-method-compare\SKILL.md`)
  프로젝트 안의 `.claude/skills/`에는 넣지 마세요. 섹션 구조의 일부가 되어 비교를 흐립니다.
- **Claude 앱**: 스킬 화면에서 `SKILL.md`를 업로드합니다.

### 3. 기록 훅 — 가장 쉬운 방법 (`mc`)
섹션 폴더들을 준비한 뒤 명령 세 줄이면 됩니다.
```bash
python tools/mes-compare/mc.py install          # mc 명령 등록 (한 번만)
mc setup D:/compare/섹션1=새구조 D:/compare/섹션2=현재 D:/compare/섹션3=구조없음
mc dash                                          # 대시보드를 켜고 브라우저까지 엶
```
- `mc setup` 이 섹션마다 한 번에 하는 일: 기록 폴더 연결(기본 = 섹션들의 공통 상위/`mes-compare-data`), 구조 이름 저장, 기록 훅(파일·스킬·에이전트·토큰), **자동 시작·종료 훅**(작업을 그냥 시키면 실행이 자동으로 시작·종료되어 `mc start`/`mc end` 불필요), SVN·DB 접속 차단 훅(`--no-guard` 로 끔). 결과를 섹션별 ✓/✗ 로 보여 줍니다.
- `mc check`: 연결한 섹션마다 훅·기록 폴더·구조 이름 점검, 진행 중 실행·대시보드 상태.
- 훅은 섹션의 `.claude/settings.local.json`(개인 설정)에 들어가고, 이전 파일은 `.json.bak` 으로 남습니다. 섹션에서 **새로 여는** 세션부터 적용됩니다.

직접 하려면 섹션마다 `init --install-hooks`를 실행합니다 (기록 훅만 등록, 자동 시작·종료는 없음).

## 빠른 시작

Claude Code에서 스킬을 불러 진행하는 것을 권합니다.

> mes-ai-method-compare 스킬로 구조 비교를 준비해줘. 도구는 D:\tools\mes-compare\mes_compare.py 에 있어.
> 구조는 "현재"(지금 그대로)와 "기본"(공용 규칙·스킬 제거) 두 개로 시작하자.

직접 할 때는 아래 순서입니다. (`T` = 도구 경로)

### git
```bash
# 1) 섹션 (같은 커밋에서)
git worktree add ../기본 -b s-기본
git worktree add ../현재 -b s-현재

# 2) 구조: 섹션에서 AI 설정 파일만 바꾸고 섹션 브랜치에 커밋
cd ../기본 && git rm -r CLAUDE.md .claude/skills && git commit -m "구조: 기본"

# 3) 섹션마다 설치
cd ../기본 && python $T init --install-hooks
cd ../현재 && python $T init --install-hooks
```

### SVN
```bash
# 1) 섹션 (같은 리비전으로 폴더별 체크아웃)
svn checkout -r 1234 https://svn.example/repos/mes/trunk D:/compare/기본
svn checkout -r 1234 https://svn.example/repos/mes/trunk D:/compare/현재

# 2) 구조: 섹션에서 AI 설정 파일만 로컬로 수정 (서버에 커밋하지 않음)

# 3) 섹션마다 설치
cd D:/compare/기본 && python $T init --install-hooks
cd D:/compare/현재 && python $T init --install-hooks
```

### 실행 (작업 × 구조마다, 해당 섹션에서 새 세션으로)
```bash
python $T start --task-id T01 --task "LOT 분할 처리" --area LOT --risk 고위험 --checks-total 10
#   … Claude로 작업 (훅이 스킬·파일·에이전트·토큰·세션을 자동 기록) …
python $T end --checks-passed 10 --rework 1           # → 판정 대기
python $T reset            # 다음 작업 전 코드 되돌리기 (미리보기) → reset --yes
```

### 판정과 보기
```bash
python $T serve            # http://localhost:8765 실시간 대시보드 (판정 입력 가능) — mc dash 와 같음
# 대시보드: 구조별 비교(기준 구조 값 포함) · 토큰은 어디에 쓰였나(접힘: 기본 문맥·이전 작업 이월·파일 읽기·명령 등 용도별, 실행별 상위 항목)
#           · 작업 흐름 3D 연결(실행마다 읽은 파일·도구 호출이 둥근 덩어리, 확대·회전) · 에이전트·스킬 설명(접힘)
python $T judge --run T01:기본#1 --final 불합격 --fail-reason "재고 원복 누락" --by 홍길동
python $T build --out 구조비교_1차.html --label "1차"    # 공유용 단일 HTML
```

## 평가 방법 (Anthropic 공식 지침 반영)

과제 비교는 아래 순서로 한다. 근거: Skill authoring best practices, skill-creator 글(2026-03), "When to fold subagents"(2026-10).

1. **과제마다 새 세션.** 앞 과제 대화가 섞이면 토큰의 절반 이상이 이월분이 된다. 세 구조를 같은 과제로 동시에 돌린다 (기록 도구가 섹션별 동시 실행을 지원).
2. **정답표를 먼저 만든다.** 과제별로 맞아야 할 항목과 근거 위치(파일:줄)를 적고, 실행 뒤 결과물·답을 그 표로 채점한다. 함정 항목(헷갈리기 쉬운 이름, 공유 코드 영향, 빌드 제외 코드)을 넣는다.
3. **핵심 과제는 칸마다 3회.** 한 번으로는 가끔 깨지는 경우가 드러나지 않는다. 점수는 평균과 최저를 함께 본다.
4. **구조를 바꾼 뒤에는 같은 과제를 다시 쓰지 않는다.** 정답을 지식·스킬에 넣었다면 점수가 오르는 것은 당연하므로, 같은 성격의 새 과제로 잰다. 원칙만 넣은 경우에만 같은 과제를 다시 써도 된다.
5. **스킬 호출 점검.** 스킬마다 "불려야 하는 요청" 3개와 "불리면 안 되는 요청" 3개를 새 세션에서 던져 호출 여부를 본다. 틀리면 설명(description)부터 고친다.
6. **코드 과제는 끝날 때마다 원복**하고, 결과물은 백업 폴더에 남겨 나중에 다시 채점할 수 있게 한다.
7. **기록 대상은 점수·시간·호출 수·토큰 네 가지.** 토큰은 캐시 읽기가 대부분이므로 요금 비교가 필요하면 입력·캐시 쓰기·캐시 읽기·출력을 나눠 본다.

## 명령

| 명령 | 설명 |
|---|---|
| `init [--install-hooks]` | 기록 폴더 준비, 섹션에 훅 등록, 이 섹션의 구조 요약 출력 |
| `structure` | 섹션의 AI 구조(에이전트·스킬·규칙·지문)와 코드·문서 지문(JSON) |
| `plan` | 실행 예정 등록 |
| `start` | 실행 시작. 구조 스냅샷·코드 지문·리비전 자동 기록 |
| `event` | 훅을 못 쓸 때 스킬·파일·에이전트·토큰·메모 수동 기록 |
| `end` | AI 작업 종료 → 판정 대기 (합격 여부는 넣지 않음) |
| `judge` | 사람 판정 (`--run` 또는 `--task-id`+`--structure`, 같은 작업 ID가 여러 프로젝트에 있으면 `--project`) |
| `reset [--yes]` | AI 설정은 두고 코드·문서 변경만 되돌림 (기본 미리보기) |
| `capture --out <묶음 폴더> [--include 경로]` | 섹션의 구조 파일을 경로 그대로 구조 묶음에 담기 |
| `apply <묶음 폴더> [--yes]` | 구조 묶음을 섹션에 적용 (기본 미리보기) |
| `serve` | 실시간 대시보드 |
| `build` | 단일 HTML 스냅샷 + 경고 출력 |
| `status` | 텍스트 요약 |
| `hook` | Claude Code 훅 진입점 (직접 쓰지 않음) |

공통 옵션 `--dir`: 기록 폴더 지정. 기본 순서는 `--dir` → 환경변수 `MES_DIR` → 섹션의 `.mes-dir` → (git) 원본 저장소 `.mes/` → (SVN·기타) 섹션 옆 `mes-compare-data/`.

## 구조 묶음: 다른 섹션·다른 PC에 구조 그대로 적용

구조(규칙 MD·에이전트·스킬·설정·도구)를 **구조 묶음** 폴더 하나로 담아 두고, 다른 섹션에서는 명령 하나로 적용합니다. 구조 묶음 폴더들을 비공개 git 저장소에 두면 다른 PC에서도 받아서 그대로 씁니다. 회사 규칙이 들어가므로 **공개 저장소에 올리지 마세요.**

```
ai-structure-profiles/        ← 비공개 저장소 (예)
 ├─ 현재/                      ← 구조 묶음 = 섹션과 같은 경로로 파일을 둔 폴더 + profile.json
 │   ├─ CLAUDE.local.md
 │   ├─ products/MES/AGENTS.md …
 │   ├─ .claude/agents, .claude/skills, .claude/settings.local.json
 │   └─ .claude/imported/…     ← 섹션 밖에서 @import 하던 파일
 └─ 리뷰/                      ← 현재를 복사해 고친 새 구조
```

```bash
# 1) 지금 쓰는 구조 담기 (원본 폴더는 읽기만 함)
cd <지금 작업 폴더>
python $T capture --out ../ai-structure-profiles/현재 --include tools/my-tool

# 2) 섹션에 적용 (미리보기 → --yes)
cd <섹션 폴더>
python $T apply ../ai-structure-profiles/현재 --yes
```

`capture`
- `CLAUDE.md`·`CLAUDE.local.md`, `.claude/` 전체, `.mcp.json`, `ai_files`, `@import` 로 불러오는 파일을 자동으로 담습니다.
- **섹션 밖 `@import` 파일**은 묶음의 `.claude/imported/` 아래로 넣고, `@경로`를 묶음 안 복사본을 가리키게 바꿉니다. 다른 PC에 같은 경로가 없어도 되고, 구조마다 내용을 달리해도 서로 덮어쓰지 않습니다.
- 규칙 문장에서만 언급되는 도구·폴더는 자동으로 찾지 못하므로 `--include`로 넣습니다. 도움이 되도록 저장소에 **등록되지 않은 파일·폴더**를 후보로 보여줍니다(빌드 산출물은 생략).
- `settings.local.json`의 비교 훅은 빼고 담습니다(섹션마다 `init --install-hooks`로 설치).
- 이미 있는 묶음은 `--yes`일 때만 덮어씁니다.

`apply`
- 묶음 폴더의 **실제 내용**을 적용합니다. 묶음을 손으로 고쳐 새 구조를 만들어도 됩니다(파일 추가·삭제 포함).
- 바뀌거나 지워지는 파일은 `.mes-profile-backup/<시각>/`에 먼저 백업합니다.
- 전에 적용한 구조에만 있던 파일은 지웁니다(구조가 섞이지 않게). 설치된 비교 훅은 유지합니다.
- 적용한 구조 이름을 `.mes-profile.json`에 남기고, 대시보드의 구조 설명에 표시합니다. 적용한 파일은 구조 파일로 취급돼 `reset`·코드 지문에서 빠집니다.

## 대시보드

- **지금 진행 상황**: 진행 중 실행의 현재 에이전트·스킬·파일·경과·토큰, 멈춤 의심(5분 무기록), 섹션 불일치, 세션 섞임 / 사람 판정 목록 / 최근 활동
- **구조별 비교표**: 모든 구조를 기준 구조와 같은 작업끼리 비교 — 합격률, 첫 시도 합격률, 평균 토큰, 평균 시간, 판정 엇갈림 + 채택 판단(채택 후보 / 효과 부족 / 품질 하락 / 표본 부족). 채택 기준은 화면에서 조정
- **기준 vs 비교 상세**, **프로젝트별 막대그래프**
- **작업 흐름**: ① 프로젝트 → ② 구조(또는 실행) → ③ 에이전트 → ④ 스킬 → ⑤ 참조 파일(규칙·지침 / 설계 문서 / 소스 코드). 실제 사용은 실선, 구성에만 있고 안 쓴 것은 점선, 지금 사용 중은 강조, 실행 하나를 고르면 사용 순서 번호
- **구조 구성**, **실제 사용한 스킬**

`examples/구조비교_예시.html`을 열면 시험 데이터로 만든 화면을 볼 수 있습니다(숫자는 시험값).

### 집계 규칙
- 같은 프로젝트의 같은 작업 ID를 두 구조가 모두 실행한 경우만 비교합니다. 프로젝트가 다르면 작업 ID가 같아도 다른 작업입니다.
- 합격률: 작업마다 판정된 실행의 합격 비율 → 작업 평균 (반복 실행 포함). 첫 시도 합격률은 재작업 0회 합격.
- 토큰·시간: 양쪽 모두 합격한 실행이 있고 그 지표가 측정된 작업만, 합격 실행 평균으로 비교. 토큰과 시간은 따로 판정.
- 토큰 = 실행 시작 이후, 실행을 시작한 세션과 하위 에이전트의 대화 기록(transcript) usage 합계 (input + output + cache_creation + cache_read). 응답 하나가 여러 줄로 기록돼도 `message.id`로 한 번만 셉니다. `end`가 마지막 턴까지 직접 계산합니다. 기준을 바꾸려면 코드의 `TOKEN_FIELDS`.
- 시간 = AI 작업 시작~종료 (판정 대기 시간 제외).

## 설정 (`<기록 폴더>/setup.json`, 선택)

```json
{
  "baseline": "기본",
  "ai_files": ["**/AGENTS.md"],
  "fixed_refs": ["D:/notes/설계 보관함/**/*.md"],
  "criteria": { "rate_drop_max": 0, "token_cut_min": 10, "time_cut_min": 0, "min_tasks": 5 },
  "structures": {
    "리뷰": { "display": "현재 + 독립 리뷰", "agent_skills": { "검증-담당": "변경검증" } }
  }
}
```

| 키 | 뜻 |
|---|---|
| `baseline` | 기준 구조 (없으면 처음 실행된 구조) |
| `ai_files` | 섹션 안에서 **구조(AI 설정)** 로 볼 파일 패턴(섹션 기준 상대 경로). 기본 AI 설정 파일 외에 규칙으로 쓰는 MD(예: 하위 폴더의 `AGENTS.md`)를 넣습니다. 구조 지문에 들어가고, 코드·문서 지문과 `reset` 대상에서 빠집니다. `**/X`는 모든 폴더의 X(최상위 포함) |
| `fixed_refs` | 모든 구조에 **같아야 하는 참조 문서** 패턴. 섹션 밖 절대 경로도 됩니다(예: 옵시디언 보관함의 설계 노트). `start`마다 내용 지문을 남기고, 같은 작업의 실행 사이에 바뀌면 경고합니다 |
| `criteria.rate_drop_max` | 허용하는 합격률 하락 (%p) |
| `criteria.token_cut_min` / `time_cut_min` | 채택에 필요한 토큰·시간 절감 (%) |
| `criteria.min_tasks` | 결론을 내기 위한 최소 비교 작업 수 |
| `structures.<이름>.display` | 화면에 보일 설명 |
| `structures.<이름>.agent_skills` | 에이전트별 스킬 (작업 흐름의 "구성됐지만 안 씀" 판단 기준) |

## 경고 (build·대시보드)

| 경고 | 뜻 / 조치 |
|---|---|
| 구조마다 코드·문서가 다름 | 같은 작업인데 참조 코드가 다름. 섹션을 같은 커밋·리비전으로 맞추세요 |
| 커밋 안 된 코드 변경 | 시작 시 코드·문서에 로컬 변경이 있었음. `reset`으로 정리 후 시작 |
| 리비전 섞임 (SVN) | 작업 폴더에 여러 리비전이 섞임. `svn update -r <리비전>` |
| 다른 섹션에서 작업 | 세션이 실행을 시작한 섹션 밖에서 작업함 |
| 세션 여러 개 섞임 | 한 실행에 세션이 2개 이상. 실행마다 새 세션 하나로 |
| 스킬 미호출 | 구조에 스킬이 있는데 한 번도 안 부름 → 구조가 실제로 적용됐는지 확인 |
| 구조 변경됨 | 비교 도중 같은 이름의 구조가 바뀜 → v1·v2로 나눠 집계 |
| @import 파일이 코드·문서로 취급됨 | `CLAUDE.md` 등이 `@경로`로 불러오는 섹션 안 파일이 AI 설정으로 분류되지 않음 → `ai_files`에 추가 |
| 고정 참조 문서가 바뀜 | `fixed_refs` 문서가 같은 작업의 실행 사이에 바뀜 → 비교 도중 참조 문서를 고치지 않기 |
| 섹션 밖 공용 규칙 | 모든 구조가 같은 섹션 밖 파일을 불러옴 → 그 파일은 구조 차이에 영향 없음 (참고) |

### 참조 MD 나누기
- **구조로 바꿀 MD**: 섹션마다 `CLAUDE.md`·`CLAUDE.local.md`의 `@경로` 목록을 다르게 둡니다. 도구가 `@import`를 최대 5단계까지 따라가 불러온 파일 내용을 구조 지문에 넣습니다(코드 블록·인라인 코드 안의 `@`와 이메일은 무시). 섹션 안 파일이면 `ai_files`에도 넣어야 코드·문서와 섞이지 않습니다.
- **고정할 MD**: 설계 노트처럼 모든 구조가 똑같이 읽어야 하는 문서는 섹션 안이면 그대로 두고(코드·문서 지문으로 확인), 섹션 밖이면 `fixed_refs`에 넣습니다.
- `@import`로 불러온 파일은 Claude Code가 자동으로 읽으므로 훅의 "실제 사용한 파일"에는 남지 않습니다.
| 판정 대기 | 사람 판정 전이라 집계에서 빠짐 |

## 주의와 한계

- **사용자 설정은 모든 섹션에 공통**: `~/.claude/CLAUDE.md`, `~/.claude/skills`·`agents`, 플러그인, 섹션 상위 폴더의 `CLAUDE.md`는 모든 구조에 똑같이 들어갑니다. 공용 규칙이 여기 있으면 구조 차이가 흐려집니다.
- **새 세션부터 적용**: 훅과 바뀐 구조는 Claude Code 세션을 새로 열어야 적용됩니다.
- **한 번에 한 실행**: 기록 폴더 하나에서 동시에 한 실행만 진행됩니다. 병렬로 돌리려면 `--dir`로 기록 폴더를 나누세요.
- **훅 입력 형식**: Claude Code 버전에 따라 훅이 받는 필드가 다를 수 있습니다. 처음 실행 후 `<기록 폴더>/events.jsonl`에 스킬·파일·에이전트 기록이 남는지 확인하세요. 훅 입력에 `agent_type`이 오는 버전에서는 그 값으로 에이전트를 구분합니다. 오지 않는 버전에서는 Agent 호출 순서로 추정하므로 병렬 하위 에이전트는 구분이 부정확할 수 있습니다.
- **SVN**: 실제 SVN 환경에서의 검증은 아직 충분하지 않습니다. 처음 쓸 때 `structure`로 리비전과 코드·문서 지문이 제대로 나오는지 확인하세요.
- **판정은 사람**: AI는 `end`까지만 기록합니다. 자동 검증 통과 수는 참고 값입니다.

## 기록되는 데이터

모두 내 컴퓨터의 기록 폴더에만 저장됩니다.
- `events.jsonl`: 실행 시작·종료, 스킬·파일 이름, 에이전트 이름, 토큰 합계, 판정 (코드 내용은 저장하지 않음)
- `setup.json`: 설정
- `current.json`: 진행 중 실행 (종료 시 삭제)

기록 폴더는 저장소에 올리지 않는 것을 권합니다(git이면 `.gitignore`에 `.mes/`).
