    구조별 비교

    각 구조를 기준 구조와 같은 작업끼리만 맞대어 비교합니다. 합격률은 사람 판정 기준이고, 토큰·시간은 양쪽 모두 합격한 작업만 평균합니다. 행을 누르면 아래에서 기준 구조와 자세히 비교합니다.

    채택 기준: 합격률 하락 %p 이내 · 토큰 절감 % 이상 · 시간 절감 % 이상 · 비교 작업 개 이상

    프로젝트별 비교

    프로젝트마다 기준 구조와 비교 구조의 막대를 나란히 놓았습니다. 토큰·시간·재작업은 짧을수록, 합격률은 길수록 좋습니다. 괄호는 집계에 들어간 작업 수입니다.

    작업 흐름

    ① 프로젝트 → ② 구조(또는 실행) → ③ 에이전트 → ④ 스킬 → ⑤ 참조 파일(규칙·지침 / 설계 문서 / 소스 코드) 순서입니다. 선은 실제로 그 에이전트가 스킬을 부르거나 파일을 읽은 기록이고, 굵을수록 여러 실행에서 쓴 것입니다. 점선은 구조에는 있지만 쓰지 않은 것, 빛나는 노드는 지금 사용 중인 것입니다. 실행 하나를 고르면 사용 순서 번호가 붙습니다.

    구조 구성

    실행할 때 섹션에서 자동으로 읽은 AI 사용 구조입니다. 지문이 같으면 같은 구조입니다.

    실제 사용한 스킬

    같은 작업 중 각 스킬을 호출한 실행 수입니다.

    집계 기준
    비교 단위
    같은 작업 ID를 두 구조가 모두 실행한 경우만 비교합니다. 구조(섹션)마다 작업 종류·개수가 달라도 왜곡되지 않습니다.
    구조
    실행 시작 때 섹션의 .claude/agents, .claude/skills, CLAUDE.md, 규칙·명령 파일, 플러그인 설정을 읽어 지문을 만듭니다. 같은 이름인데 지문이 바뀌면 v1·v2로 나눠 집계합니다.
    판정
    AI 작업이 끝나면 ‘판정 대기’, 사람이 합격·불합격을 넣으면 ‘완료’. 자동 검증 통과 수는 참고 값입니다.
    합격률
    작업마다 판정된 실행의 합격 비율을 구하고, 작업들의 평균을 냅니다(반복 실행 포함).
    첫 시도 합격률
    재작업 없이(재작업 0회) 합격한 비율입니다.
    토큰·시간
    양쪽 모두 합격한 실행이 있고 그 지표가 측정된 작업만, 합격한 실행의 평균으로 비교합니다. 토큰과 시간은 따로 판정합니다. 시간은 AI 작업 시작~종료입니다.
    판정 엇갈림
    같은 작업·같은 구조를 여러 번 돌렸을 때 합격과 불합격이 섞인 경우입니다. 많으면 결과가 불안정하다는 뜻입니다.
    경고
    시작 커밋이 구조마다 다름(참조 코드·문서 불일치), 커밋 안 된 코드 변경, 다른 섹션에서 작업, 한 실행에 세션 여러 개, 구조에 스킬이 있는데 미호출.
