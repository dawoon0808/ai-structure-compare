# AI 사용 구조 비교

목표: 참조하는 코드·문서는 그대로 두고 AI 사용 구조만 바꿔서, 같은 품질에 토큰·시간이 가장 적게 드는 구조를 고른다.
도구는 `mes_compare.py`(Python 3.8+ 표준 라이브러리만) 파일 하나다. 서버(git 원격·SVN)에 올릴 필요 없이 내 컴퓨터 아무 폴더에 두면 된다.

## 개념
- **섹션** = 구조 하나 = 작업 폴더 하나. 같은 코드를 폴더 여러 개로 받아 두고, 폴더마다 AI 설정만 다르게 둔다. 폴더 이름이 구조 이름이 된다.
- **AI 설정 파일**(구조) = `CLAUDE.md`, `CLAUDE.local.md`, `.claude/**`, `.mcp.json`, 이 파일들이 `@경로`로 불러오는 파일, `setup.json`의 `ai_files`. 그 외 모든 파일(코드, `docs/` 설계 문서 등)은 **참조 코드·문서**로, 모든 섹션에서 같아야 한다. 섹션 밖 참조 문서는 `fixed_refs`로 고정 여부를 확인한다.
- **세션** = 실행 하나. 섹션 안에서 작업 하나를 할 때마다 새 세션을 연다.
- **비교** = 같은 작업 ID를 두 구조가 실행한 것끼리. 섹션 전체끼리 비교하지 않는다.
- **합격·불합격은 사람이 판정한다.** AI는 `end`까지만 기록하고 `judge`를 스스로 실행하지 않는다.
- 토큰·시간·스킬·파일은 추정하지 않는다. 훅 기록·실측값만 쓴다.

## 1. 준비 (구조마다 한 번)
1. **도구 확인**: 사용자가 알려준 경로(예: `D:\tools\mes-compare\mes_compare.py`)에 도구가 있는지 본다. 없으면 직접 작성하지 말고 사용자에게 파일 위치를 묻는다. 확인: `python <도구> --help`.
2. **섹션 만들기** (사용자와 구조 이름·내용을 정한 뒤). 섹션 폴더들은 **한 상위 폴더 아래에 나란히** 둔다.
   - git: `git worktree add ../<구조이름> -b s-<구조이름>` (모든 섹션을 같은 커밋에서)
   - SVN: `svn checkout -r <리비전> <URL> <상위폴더>/<구조이름>` (모든 섹션을 같은 리비전으로)
3. **구조 만들기**: 각 섹션에서 **AI 설정 파일만** 추가·수정·삭제한다(예: 기준 구조는 공용 스킬·규칙 제거, 리뷰 구조는 검증 에이전트 추가). 코드·문서는 건드리지 않는다.
   - **구조 묶음 사용(권장)**: 사용자가 구조 묶음 폴더(예: 비공개 저장소 `ai-structure-profiles/현재`)를 알려주면 섹션에서 `python <도구> apply <묶음>`으로 미리보기를 보여주고, 사용자 확인 후 `--yes`로 적용한다. 지금 쓰는 구조를 담을 때는 원래 작업 폴더에서 `capture --out <묶음>`을 실행하고, 출력된 '등록되지 않은 파일' 후보 중 구조에 필요한 도구·폴더를 사용자와 정해 `--include`로 다시 담는다. 새 구조는 묶음 폴더를 복사해 고친다. 묶음에는 회사 규칙이 들어가므로 공개 저장소에 올리지 않는다.
   - git: 그 섹션 브랜치에 커밋해 둔다(작업 후 되돌려도 구조가 유지되게).
   - SVN: 로컬에서만 바꾸고 **서버에 커밋하지 않는다**.
4. **섹션 밖 설정 확인**: 사용자 설정(`~/.claude/CLAUDE.md`, `~/.claude/skills`·`agents`, 설치된 플러그인)과 섹션 상위 폴더의 `CLAUDE.md`는 모든 섹션에 똑같이 적용돼 차이를 흐린다. 있으면 사용자에게 알린다. (이 스킬 자체는 사용자 설정에 있어도 모든 섹션에 같으므로 괜찮다.)
5. **섹션마다 설치**: `cd <섹션> && python <도구> init --install-hooks`
   - 훅은 그 섹션의 `.claude/settings.local.json`(개인 설정)에 등록된다. 기존 파일은 `.bak` 백업. 등록 전 사용자에게 알린다.
   - 기록 폴더: git은 원본 저장소의 `.mes/`, SVN·기타는 섹션들 옆 `mes-compare-data/`. 섹션의 `.mes-dir` 파일에 기록되며, 모든 섹션이 같은 기록 폴더를 가리키는지 확인한다.
   - 출력된 구조(에이전트·스킬·규칙 수·지문)가 의도와 맞는지 사용자에게 확인한다. `python <도구> structure`로 구조 지문과 **코드·문서 지문**을 다시 볼 수 있고, 모든 섹션의 코드·문서 지문이 같아야 한다.
6. 선택: 기록 폴더의 `setup.json`에서 `baseline`(기준 구조), `criteria`(채택 기준: 합격률 하락 허용 %p, 토큰·시간 절감 %, 최소 작업 수), 구조별 `display`(설명), `agent_skills`(에이전트별 스킬) 지정.
   - **참조 MD 나누기**: `init`/`start`가 `@import`로 불러오는 섹션 안 파일이 코드·문서로 취급된다고 경고하면, 사용자와 확인해 `ai_files`(예: `"**/AGENTS.md"`)에 넣는다. 섹션 밖의 설계 노트처럼 모든 구조에 같아야 하는 문서는 `fixed_refs`(절대 경로 패턴)에 넣는다. 규칙 MD와 참조 MD가 한 폴더에 섞여 있으면 폴더 전체가 아니라 파일·하위 폴더 단위로 나눈다.
7. 훅과 바뀐 구조는 **새 세션부터** 적용된다.

## 2. 실행 (작업 × 구조마다, 해당 섹션의 새 세션에서)
```
python <도구> start --task-id T01 --task "LOT 분할 처리" --area LOT --risk 고위험 --checks-total 10
  ... 작업 (훅이 스킬·파일·하위 에이전트·토큰·세션을 자동 기록) ...
python <도구> end --checks-passed 10 --rework 1 --note "자동 검증 통과"      # → 판정 대기
python <도구> reset            # 다음 작업 전: 미리보기 → 사용자 확인 후 reset --yes
```
- 구조 이름(섹션 폴더 이름), 프로젝트(저장소 이름), 구조 스냅샷, 코드·문서 지문은 `start`가 자동 기록한다.
- 같은 작업은 모든 섹션에서 **같은 작업 ID·같은 설명**으로 돌린다.
- `reset`은 AI 설정은 남기고 코드·문서 변경만 되돌린다(새로 생긴 파일 삭제 포함). 기본은 미리보기이며, 사용자 확인 후 `--yes`로 실행한다.
- 같은 작업·구조를 다시 돌리면 반복 실행(#2, #3)으로 쌓인다. 핵심 작업은 2회 이상 권장.
- 한 기록 폴더에서는 한 번에 한 실행만 진행한다.
- 훅을 못 쓰면 `event --type skill|file|agent|agent_end|tokens|note --name … [--agent …] [--total N]`.

## 3. 사람 판정
- 대시보드의 '사람 판정 필요'에서 입력하거나 `python <도구> judge --run T01:기본#1 --final 불합격 --fail-reason "…" --by 홍길동` (`--task-id`+`--structure`로도 가능). 불합격은 사유 필수.

## 4. 보기
- 실시간: `python <도구> serve` → http://localhost:8765 (5초 갱신)
- 스냅샷 공유: `python <도구> build --out 구조비교_<날짜>.html --label "<회차>"`
- 텍스트: `python <도구> status`

## 5. 보고
`build`의 경고(코드·문서 지문 불일치, 미반영 코드 변경, 리비전 섞임, 섹션 불일치, 세션 섞임, 스킬 미호출, 구조 변경, 판정 대기)를 먼저 전하고, 기준 대비 각 구조의 합격률·토큰·시간 차이와 채택 판단을 한두 문장으로 보고한다. 표본이 기준보다 적으면 결론을 내리지 않는다. 판정되지 않은 결과를 합격처럼 말하지 않는다.
